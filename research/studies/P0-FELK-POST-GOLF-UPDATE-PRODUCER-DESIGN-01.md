3. 4. Missing prospective build/process/backend evidence implies ABSTAIN for any future runtime experiment, without invalidating the older source-only banks. This design does not authorize compiling, attaching or running anything.

**Stage 1, distinguish scene invocation from physics substep** — Source `fn_8028DFA8` is a **tail-branch thunk** to `fn_8028E158`, so attaching to a supposed direct call-return at the thunk PC is incorrect. The callee contains conditional branches, indirect control and three possible SimulateManager calls. Owner must identify the actual **executed update epilogue / return path(s)** and how each path maps to a *ball integrator* step, not merely to an OnCalculate invocation. A post-main-return counter may be a **scene calculate counter**, not a physics-step count. Distinguish counters in names and schema: `scene_calculate_exit_id` and `guest_ball_physics_step_id` must not be conflated.

**Stage 2, only if source proves a feasible execution hook** — Propose a *disabled-by-default*, CPU-thread native producer in the **selected actual backend** at a site executed *after* the real guest update, never at a breakpoint lookup or code compilation pass. If the needed site is in emitted JIT code, preserve CPU/GPR/FPR/CR/LR, exception/branch semantics, block linking and ABI; review against interpreter mode as a correctness oracle but do not assume interpreter timing is identical to JIT. Avoid patching guest RAM or pausing emulation. Require a code-review-approved way to observe early exits, conditional paths, exceptions, reentrant calls and scene transitions; count only fully completed, source-identified updates. A host callback timestamp is not a guest time unit.

**Stage 3, in-hook read and bounded provenance** — For a verified stable Golf scene/mode/hole/player and ball-owner source, capture selected roster ball, **separate** source-global ball, selected CC cache, start/pin/config controls **inside the SAME execution callback**. Validate native bank spans, full source pointer chains, object distinctness and before/after scene-owner stability. Never call Python/bridge memory API or take a screenshot from the CPU hook without a separate reentrancy and overhead proof. Use a bounded private native buffer of *categorical data* for the first no-input pilot; original raw vectors remain local and do not appear in PR comments. Reject if callback duration >5 ms, queue overflow, wrong backend, missing physics-step ID, changed ownership, interpreter/JIT disagreements or any guest write.

**Stage 4, independent visual correlation** — Only after a genuine guest physics-step source is attested, have rendering owner design a *separate* actor-ID/submit-frame witness with a trusted source join token (or honestly mark it absent). Neither `FrameDrawn` RGB bytes nor VI `FrameAdvance` alone provides that join. Pixel observation without a typed ball-render submission stays visual hypothesis, not `actual_ball_world_xyz_verified`.

**Stage 5, operator trial (later, not now)** — First owner-approved **no-input** stationary pilot, with offline review of strictly categorical samples, exact source/build pin, same-hook and timing failure modes; only then consider one human-supervised shot. Absolutely no autonomous shot, automatic overlay or frame-capture experiment during this design phase. S000/S001/S002 must approve safety, privacy, simulator noninterference and data-training gates.

## Higher-ROI native execution witness discovered: preexisting cross-core HLE Start hooks

A second source audit found a more concrete, reusable **native executed-function-entry** mechanism than inventing a new from-scratch per-instruction JIT callback. This is source-only; there is **NO registered Golf hook** in the examined public fork, and NO post-update witness yet.

- [`Source/Core/Core/HLE/HLE.cpp`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/HLE/HLE.cpp), Git blob **`66d0960821d671114b9da329e24bde57f6874dac`**, defines a **fixed table of 23 `os_patches`** (including placeholder, OS debug log, fixed HBReload/Gecko/AppLoader functions). `HLE::Patch` searches this table by existing function name; it is NOT an arbitrary user-provided handler or automatic Python hook. `HLE::PatchFunctions` maps symbol names and invalidates JIT/iCache; `TryReplaceFunction` requires a matching function entry or a specially registered fixed address, a valid `HookType::{Start,Replace}`, and enabled flags. A future custom `Golf...` observer would require an **explicit audited emulator source change + rebuilt, separately attested binary** and JIT invalidation testing.
- [`Source/Core/Core/HLE/HLE.h`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/HLE/HLE.h), Git blob **`e3ffc3d03c055f5f2932ca0a191c103633f81f0a`**, types registered functions with `HookType::Start` versus `HookType::Replace`. Selecting Replace to collect telemetry is **not observational**: it can skip original game code, so fail closed on Replace for an instrumentation-only plan.
- [`PowerPC/Jit64/Jit.cpp`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/PowerPC/Jit64/Jit.cpp), blob **`b09279d45850a8ad0b14b5ad1ffb60c401cad3f0`**, `Jit64::HandleFunctionHooking` queries HLE while **generating** code, but **emits** `HLEFunction(hook_index)` at that guest instruction site; `HLEFunction` emits an ABI-managed runtime `HLE::ExecuteFromJIT` call, flushing registers and saving host caller state. For `HookType::Start`, the handler then returns FALSE so the **original guest instruction compilation continues**. **Crucial distinction:** lookup/compilation is not a witness, but the emitted runtime `HLE::ExecuteFromJIT` function body is intended to run when the compiled guest site is EXECUTED. This can potentially supply a native **function-entry** witness on a rebuilt fork (subject to validation).
- [`PowerPC/CachedInterpreter/CachedInterpreter.cpp`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/PowerPC/CachedInterpreter/CachedInterpreter.cpp), blob **`b281ac0300bb750c12b2ede6f4e7e7d7536a7304`**, writes an `HLEFunction` callback into executable cached block at a mapped address; a Start hook leaves the subsequent original instruction in the block. Runtime callback calls `HLE::Execute(Core::CPUThreadGuard{system},...)`. Compare this path with JIT64; do not count code-generation call to `HandleFunctionHooking`.
- [`PowerPC/Interpreter/Interpreter.cpp`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/PowerPC/Interpreter/Interpreter.cpp), blob **`89153f801e5204e2c54ad3458611bc4f5baf5381`**, checks `TryReplaceFunction` before running the instruction. A Start hook invokes the handler **before** the guest instruction but then does **not** consume the instruction; Replace does. This is a potential interpreter control comparison, not guest physics evidence.
- `HLE::ExecuteFromJIT` asserts CPU thread and constructs a `CPUThreadGuard`, then dispatches only registered hook-index functions. The known HLE code is a *bounded native mechanism*, not proof a new callback can safely call public Python/bridge memory APIs, allocate, block, or finish under 5ms. No guest-scene return, physics-step ID, or rendering join is provided by HLE.

**High-information owner decision:** consider **an internally registered, disabled-by-default HLE `Start` hook solely as a source-backed *executed entry* witness** for a real Golf function in a newly built instrumented Felk fork, rather than claiming no JIT-compatible execution hook concept exists. The final target must use stable exact Rev1 symbols/source gates and avoid replacing game behavior. Before any run, demonstrate that `HLE::PatchFunctions` does not silently attach by incorrect symbol alias or across all interior addresses, JIT cache invalidations work, all CPU backends have corresponding execution timing, and reentrancy/ABI/memory access are safe.

**Hard NO-GO for completed physics state:** HLE Start fires **BEFORE** original guest function execution. A Start hook at `OnCalculate` / `fn_8028E158` cannot attest its **exit**, distinguish conditional paths, establish that the ball integrator ran, or guarantee same guest physics-step timing. A separate validated after-execution witness is still required. Do not turn entry count into `guest_ball_physics_step_id`, use `HookType::Replace`, patch guest instructions, or run an unreviewed local executable. An HLE handler inserted into a custom build requires independent source/build match, deterministic no-input controls and owner S001/S000 approval. This note is a source-level **possible implementation reduction**, not runtime GO authorization.

### Specific follow-up: HLE Fixed+Start can target a *proven guest code-site*, not only a symbol entry

The upstream native HLE API offers an additional *conditional implementation option* worth explicitly recording. In `HLE.cpp` blob `66d096...`, `Patch(system, addr, func_name)` maps a registered hook **to the specified guest address** and invalidates iCache/JIT, while `GetHookByFunctionAddress` bypasses the normal *symbol-start equality requirement* for hooks whose **registered `HookFlag` is Fixed**. `Jit64::HandleFunctionHooking(op.address)` is called in the per-guest-instruction code-generation loop and emits a runtime HLE callback at the exact mapped guest instruction PC; a custom **Fixed+Start** entry would return to compiling the **original instruction**. CachedInterpreter and Interpreter similarly support Start semantics.

**Potentially higher value than an entry-only hook:** if S002/S001 independently prove an exact Rev1 *program point after a typed ball-state update* and all relevant exit paths, a new **custom** HLE Fixed+Start hook at that subsequent guest PC could witness **executed reachability of that point** on JIT64 without a general-purpose guest instruction trace. A hook immediately before `blr` would observe the preceding path effects only if the exact BLR is actually reached and the function has no unaccounted early exits/tails. It cannot be stamped `one_guest_physics_step` without explicit update/flow qualification. An entry hook *does not* suffice for post-update evidence.

**Safety blockers:** the public `os_patches` list contains only existing OS/fixed/debug handlers; **never repurpose a named Gecko, OSReport, HBReload or existing HLE function** with `HLE::Patch` to create golf telemetry. A custom handler requires a source-reviewed new table entry, recompilation, exact executable/source build attestation, and backend-specific cache invalidation/patching checks. It must not mutate registers, guest RAM, control flow, timing or emit Python calls on CPU thread; pure-native read must satisfy measured noninterference (not asserted in this doc). A branch can simply skip an interior hook; multiply-returning or looping functions may invoke it zero/multiple times. Correctness is therefore a test obligation, not an implication of the HLE API. **No code changes, hook or runtime experiment are authorized.**

## New primary-source guard review: CPUThreadGuard has a CPU-thread fast path

At pinned public Felk preview4 `a22afcb10b97c251e17e46f2982d4e37729d32a1`, [`Core/Core.cpp`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/Core.cpp) Git blob **`77613b3befb84a269c9920822e58951ffabbe890`** defines `Core::CPUThreadGuard::CPUThreadGuard`: it saves `m_was_cpu_thread = IsCPUThread()` and calls `PauseAndLock(system, true, true)` **only if this value is false**. Its destructor likewise calls `PauseAndLock(...false...)` only on the non-CPU-thread path. [`Core/Core.h`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/Core.h) Git blob **`f9d47b366d56f80a35e828c6eb29f736336aa519`** declares this guard. Separately `HLE::ExecuteFromJIT` asserts `Core::IsCPUThread()` and constructs a guard before calling a registered native handler.

**Positive bounded consequence:** a correctly running native HLE Start handler on the emulated CPU thread does NOT inherently pause and lock the emulator **just from constructing CPUThreadGuard**. `API::Memory::Read_U32` likewise constructs a guard, so there is no *guard-specific* PauseAndLock penalty in this exact CPU-thread case. This tightens the previous generic reentrancy concern and makes a tiny zero-guest-write **native** executed-PC observer a source-plausible design, not an approved one.

**Still unverified:** performance/latency, MMU read faults, JIT ABI/FPR state, proper true after-update PC and all branch/exception exits, typed ball owner, object lifetime, guest frame, Python GIL/event listener reentrancy or GPU/frame correlation. The Python event system explicitly uses a synchronous CPU-thread callback under a mutex, so a guard fast path does NOT render arbitrary Python calls safe. For any later S001 proposal, prefer the *minimum* disabled-by-default native callback that increments one bounded private counter at the exact executed source-qualified PPC site, with no Python callbacks or game-memory reads during the initial operator-negative-control design. Owner must review/rebuild separately; **do not run it now**.

The distinction is important: `GetHookByFunctionAddress`/JIT compiler lookup is NOT an executed witness; the emitted HLE execution handler is the runtime site. HLE `Start` observes **before** its PPC instruction, not after it; only an exact guest PC independently proved to follow a completed typed physics update could be considered for a physics-step witness. No current evidence supports such a PC or one-to-one cadence. NO-GO remains.

## P0 owner review: HLE executable-site identity, lifecycle and CPU program-order acceptance

**Source-only correction. No custom native hook has been built or run.** All below are future engineering test obligations; not a request for local Dolphin, memory banks, screenshots, PowerShell, shots or training.

1. **Native callback PC is dropped before the registered handler.** Pinned Felk Preview4 HLE/HLE.h (blob e3ffc3d03c055f5f2932ca0a191c103633f81f0a) defines HookFunction taking only CPUThreadGuard. HLE/HLE.cpp (blob 66d0960821d671114b9da329e24bde57f6874dac) receives current_pc in ExecuteFromJIT and Execute, but calls os_patches[hook_index].function(guard), discarding that PC. Jit64/Jit.cpp (blob b09279d45850a8ad0b14b5ad1ffb60c401cad3f0) emits a runtime HLE call with js.compilerPC yet does not synchronize PPCSTATE.pc at this callback. Require either a uniquely reviewed fixed hook-index-to-exact-source-PC mapping or an explicitly reviewed PC-forwarding native ABI. A handler-side PPCSTATE.pc read does not certify the callback's guest PC.

2. **Reload can silently remove custom fixed mappings.** HLE::PatchFunctions retains existing Fixed maps; HLE::Reload runs Clear, then PatchFixedFunctions (which restores built-in fixed patches), then PatchFunctions (which skips Fixed registrations). A one-off new custom Fixed mapping is consequently lost absent reviewed rearming. Require synthetic register/refresh/reload/disable/enable lifecycle tests, JIT/iCache invalidate checks, no callbacks when disabled, and fail-closed missing-epoch detection after any disarm. Do not claim any particular user savestate operation invokes Reload without a separate source callsite proof.

3. **Debug hook flag is not an explicit opt-in.** HLE::IsEnabled suppresses Debug hooks under ordinary JIT debugging-off. Other flags do not automatically provide an instrument-only explicit OFF-by-default gate. Before any installation, require compiled opt-in switch, exact signed/reviewed guest game/revision/core and selected hook PC constraints; never hijack existing Gecko/OSReport/HBReload patch names.

4. **Fixed+Start timing is JIT-optimized, not automatically original PPC instruction completion.** Exact Jit64 DoJit iterates PPCAnalyst CodeOp entries after ReorderInstructions; selected independent instructions may be swapped. It calls HandleFunctionHooking(op.address) before checking op.skip, and the current skipped-op case includes a branch-following BLR optimization. A native HLE callback inserted at such a position can observe a JIT-optimized placement rather than a naive interpreter program-order boundary. For any proposed after-update PC, require source-proven ordering barrier or a reviewed JIT instrumentation fence. Negative controls must exercise an independent compare/ALU reorder, skipped BLR, branch linking/fast return, early exits/exceptions and multiple/zero callbacks, against interpreter and cached-interpreter behavior. Bare emitted-hook invocation is NOT an executed completed ball physics step.

5. **Keep evidence clocks distinct.** An executed-site observer earns only executed_site_id. A proven actual scene callback completion may earn scene_calculate_exit_id if all relevant exit paths are covered. Only separately source-typed ball-state integrator completion and cadence can earn guest_ball_physics_step_id. Same-hook selected/global/CC capture and an independent renderer actor/time join require further distinct witnesses. The public CPUThreadGuard fast-path in Core/Core.cpp (blob 77613b3befb84a269c9920822e58951ffabbe890) avoids PauseAndLock on a correctly identified CPU thread; this does not prove native read safety or Python/GIL reentrancy. Do not add persistent CPU-thread Python event listeners as a shortcut.

**Decision stays NO-GO** for compiling or running experimental hooks, user-controlled shots, inferred position/velocity/impact/distance, publication and training until S001/S002/S000 approvals and prospective build/runtime proofs.


### Specific source-backed CPU-thread read failure contract: MMU HostTryReadU32 vs HostRead_U32

A hypothetical Golf HLE handler must **not** mistake `0` returned by a failed native memory read for a valid score/ball field. Public Felk Preview4 [`Source/Core/Core/PowerPC/MMU.h`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/PowerPC/MMU.h), immutable Git blob `fe0e127a772202ca26a49259ad168ead33184113`, lines 119–145, distinguishes:

- `MMU::HostRead_U32(const CPUThreadGuard&, guest_addr)` — debugger/cheat host API whose documented failed mapping **raises a user-visible PanicAlert and returns zero**. Inadmissible as a silent telemetry reader if a pointer source relocates.
- `MMU::HostTryReadU32(const CPUThreadGuard&, guest_addr, RequestedAddressSpace::Effective)` — returns `std::optional<ReadResult<u32>>`, with a **no-alert invalid-mapping signal**. [`MMU.cpp`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/PowerPC/MMU.cpp), blob `07b59fc7dffeb8c794867bbc8db14c37dc3b8901`, lines 620–650, 665–669, checks `HostIsRAMAddress` and returns `std::nullopt` on disqualification; this must **ABSTAIN**, never coerce to zero. Verify Effective address space / active guest translation before accepting the original MEM2 source objects; no silent physical alias fallback.
