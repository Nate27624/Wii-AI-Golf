# P0 S001 — execution-qualified post-Golf-update producer: source-backed GO/NO-GO

**Decision: NO-GO for live hook, no-input dual-ball pilot, shot, world XYZ, velocity and training.** This is an owner-review design only. No code instrumentation, emulator/game process, breakpoint, controller, frame capture or original private RAM is touched. Do not request another executable-finder script or marker scan; prior native marker-positive has already been recorded in #282/#272.

## Additional *new* Felk CPU backend evidence (pinned public source)

Inspected exact [Felk/dolphin commit `a22afcb10b97c251e17e46f2982d4e37729d32a1`](https://github.com/Felk/dolphin/tree/a22afcb10b97c251e17e46f2982d4e37729d32a1). The following are source facts, **not observed installed-binary runtime behavior**:

1. [`PowerPC/PowerPC.cpp`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/PowerPC/PowerPC.cpp), Git blob `3cc1112bd7bf31db3570aa24ecce29d75c1a3ee4`, selects **Interpreter**, **CachedInterpreter**, or JIT by `InitializeCPUCore`. On AMD64 the public `DefaultCPUCore()` returns `CPUCore::JIT64`. `PowerPCManager::RunLoop` dispatches through the active backend's `Run()`; `SingleStep` delegates similarly. Therefore instrumenting only the C++ interpreter loop will not observe a default JIT64 execution path.
2. [`PowerPC/Interpreter/Interpreter.cpp`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/PowerPC/Interpreter/Interpreter.cpp), Git blob `89153f801e5204e2c54ad3458611bc4f5baf5381`: `SingleStepInner()` reads the guest opcode, executes via interpreter `RunInterpreterOp(...)` or exception paths, then calls `UpdatePC()`; `Run()` repeatedly calls `SingleStepInner()` in timing slices. A post-`SingleStepInner` check would be an *interpreter-only executed-instruction* possibility, **not** a default-backend hook nor a proof of completed Golf physics.
3. [`PowerPC/CachedInterpreter/CachedInterpreter.cpp`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/PowerPC/CachedInterpreter/CachedInterpreter.cpp), Git blob `b281ac0300bb750c12b2ede6f4e7e7d7536a7304`: `ExecuteOneBlock` dispatches cached callbacks, while **compilation** of cached instruction sequences also invokes breakpoint predicates. The compile-time predicate is therefore not a runtime execution witness. No safe post-instruction event is exported through the public Python wrapper.
4. [`PowerPC/Jit64/Jit.cpp`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/PowerPC/Jit64/Jit.cpp), Git blob `b09279d45850a8ad0b14b5ad1ffb60c401cad3f0`: `Jit64::Run()` executes generated machine code through `asm_routines.enter_code`, **not** `Interpreter::SingleStepInner`. Its `Jit` **code-generation pass** may call `IsAddressBreakPoint(op.address)`. Observing that check or the JIT compiler PC is not observing the *executed guest instruction*. Any JIT probe must be inserted into emitted *runtime* code (or a separately proven post-dispatch execution path) and must preserve ABI / registers / exceptions / JIT block linking. That is not implemented in this project.
5. [`API/Events.h`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/API/Events.h), Git blob `39daf9080c5c65eb3dad1467de22a1d7dab125de`: `EventContainer::EmitEvent` asserts CPU thread and synchronously invokes listeners under `m_listeners_iterate_mutex`, warning of GIL vs CPU-thread locking deadlocks. A new per-Golf-update Python event is **not** automatically safe merely because code is on the emulated CPU thread.
6. [`API/Memory.cpp`](https://github.com/Felk/dolphin/blob/a22afcb10b97c251e17e46f2982d4e37729d32a1/Source/Core/Core/API/Memory.cpp), Git blob `c63e2cf52770350971d8b4ba19856ef23cbc573d`: `API::Memory::Read_U32` constructs `Core::CPUThreadGuard` per read. Whether any proposed observer can safely acquire that guard while in a CPU-execution hook is **unverified**. An implementation must choose source-reviewed CPU-thread-safe MMU access rather than assume public Python wrappers are re-entrant.

## Minimal hypothetical native producer — implementation must be separately reviewed

**Stage 0, build/identity GO gate** — S001 owner reconciles the default and separate Clean Dolphin executables against original capture provenance, identifies the ACTUALLY used CPU core (JIT64 versus cached interpreter versus interpreter), confirms compiled revision/source modifications and game RSPE01 Rev1. A preview4 SHA string embedded in the PE is only an affinity hint. If exact source-to-binary parity or boot provenance cannot be verified, **ABSTAIN**.

**Stage 1, distinguish scene invocation from physics substep** — Source `fn_8028DFA8` is a **tail-branch thunk** to `fn_8028E158`, so attaching to a supposed direct call-return at the thunk PC is incorrect. The callee contains conditional branches, indirect control and three possible SimulateManager calls. Owner must identify the actual **executed update epilogue / return path(s)** and how each path maps to a *ball integrator* step, not merely to an OnCalculate invocation. A post-main-return counter may be a **scene calculate counter**, not a physics-step count. Distinguish counters in names and schema: `scene_calculate_exit_id` and `guest_ball_physics_step_id` must not be conflated.

**Stage 2, only if source proves a feasible execution hook** — Propose a *disabled-by-default*, CPU-thread native producer in the **selected actual backend** at a site executed *after* the real guest update, never at a breakpoint lookup or code compilation pass. If the needed site is in emitted JIT code, preserve CPU/GPR/FPR/CR/LR, exception/branch semantics, block linking and ABI; review against interpreter mode as a correctness oracle but do not assume interpreter timing is identical to JIT. Avoid patching guest RAM or pausing emulation. Require a code-review-approved way to observe early exits, conditional paths, exceptions, reentrant calls and scene transitions; count only fully completed, source-identified updates. A host callback timestamp is not a guest time unit.

**Stage 3, in-hook read and bounded provenance** — For a verified stable Golf scene/mode/hole/player and ball-owner source, capture selected roster ball, **separate** source-global ball, selected CC cache, start/pin/config controls **inside the SAME execution callback**. Validate native bank spans, full source pointer chains, object distinctness and before/after scene-owner stability. Never call Python/bridge memory API or take a screenshot from the CPU hook without a separate reentrancy and overhead proof. Use a bounded private native buffer of *categorical data* for the first no-input pilot; original raw vectors remain local and do not appear in PR comments. Reject if callback duration >5 ms, queue overflow, wrong backend, missing physics-step ID, changed ownership, interpreter/JIT disagreements or any guest write.

**Stage 4, independent visual correlation** — Only after a genuine guest physics-step source is attested, have rendering owner design a *separate* actor-ID/submit-frame witness with a trusted source join token (or honestly mark it absent). Neither `FrameDrawn` RGB bytes nor VI `FrameAdvance` alone provides that join. Pixel observation without a typed ball-render submission stays visual hypothesis, not `actual_ball_world_xyz_verified`.

**Stage 5, operator trial (later, not now)** — First owner-approved **no-input** stationary pilot, with offline review of strictly categorical samples, exact source/build pin, same-hook and timing failure modes; only then consider one human-supervised shot. Absolutely no autonomous shot, automatic overlay or frame-capture experiment during this design phase. S000/S001/S002 must approve safety, privacy, simulator noninterference and data-training gates.
