# S002 P0 — two independent source-qualified vector distance callsite analyses

## Motivation and exact novelty
The source owner [draft #256](https://github.com/Nate27624/Wii-AI-Golf/pull/256) previously ran the original B0 RSPE01 Rev1 pinned source on operator Windows and found **18 direct PPC BL calls to `PSVECSquareDistance`** in published Golf source units, alongside 14 direct `sprintf` calls. The 14 formatter-site r31/format-literal investigation is **already owned and independently tested** by #256 and must not be duplicated. Both standard Config and SequenceMgr hole-1 score tables were also negative for immediate changes. There is still no confirmed on-screen distance producer or physical ball-to-pin computation.

This isolated child of #256 adds TWO targeted, self-contained Python read-only analyzers over the **same exact 18 published Rev1 source BL callsites** (not the whole game or new floats):

* `scripts/audit_p0_golf_vec_arguments_private.py`: at each exact source BL, inspects a **<=0x80-byte bounded preceding syntactic suffix after the last recognized control-flow barrier** for register `r3` and `r4` writes. Because Wii PowerPC EABI passes the two vector-pointer arguments in r3/r4 for this library call, a last syntactic `lwz/addi/mr` candidate may guide the next source-object owner. PPC rA-write, lmw, update-form and X-form hazards produce conservative categories, never a claimed pointer. It does NOT dereference either arg or print memory/addresses.
* `scripts/audit_p0_golf_vec_f1_return_private.py`: at each exact source BL, scans **<=0x80 bytes forward**, stops at the first recognized branch/call, f1 load overwrite, floating point op or direct `stfs/stfd f1` source store. The class `F1_STFS_SOURCE_STORE_SYNTAX` identifies only an *instruction syntactically storing FPR1* after the distance call, NOT the calculated physical distance being stored in a specific object or live in a real frame. If floating arithmetic/move/paired-single or branch intervenes, it ABSTAINS rather than fabricating a return-value provenance.

## Source/format safety
Both scripts reuse **unmodified #219 original B0 manifest/SHA, RSPE01 Rev1, published 832 text-unit source index and #256's original direct BL decoder**. They require exactly **18 original direct PSVEC-square-distance BL sites**, inspect only original B0 MEM1 source-code unit bounded bytes, verify B0 SHA before and after, and serialize only public source unit names + source-relative call offsets and symbolic instruction categories/booleans. No actual `r3`, `r4`, `f1` values, private game pointer/word/hash, vector floats, format strings, file paths, heap addresses or raw native banks. Neither script starts Dolphin, sends controllers, allocates memory, writes game RAM, plays a shot, uploads data or merges. Isolated tests synthetic-only; no native B0 run in CI.

**Semantics explicitly not verified:** exact function CFG boundaries and all-path reaching defs, whether the two vector args point to source-selected ball `+0x30`, source-global ball, target/pin/cup or another game entity; whether `f1` remained the actual return from this particular BL; whether local stores executed in any shot; whether this call contributes to visible Hitting-the-Green result, distance units, world coordinates, velocity, impact, score, power, same-guest-frame labels, or model training. Human phase labels unverified and operator captures currently hole 1 only. Source-only classifications must not promote any physical field or `training_approved` flag.
